## Stack versions
Record these from this Mac the first time a session runs here; never assume them.
- **Xcode / Swift:** Xcode 16.2 (build 16C5032a, installed 2026-11-16); Swift 6.0.3, language mode 5.
- **Minimum macOS:** 14 — my own Mac is on macOS 14.8.7 (2026-11-16); the target Mac is brand new.
- **Signing:** a free Apple ID (Personal Team, "Apple Development"), no paid account, so no notarization (spec B). The team ID is in the untracked `mac/Local.xcconfig` (`DEVELOPMENT_TEAM = …`, shape in `Local.xcconfig.example`) and never in the repo. The certificate was only valid on this Mac once Apple's "WWDR G3" intermediate certificate was in the login keychain (2026-11-17); `security find-identity -v -p codesigning` must show one valid identity.
- **Tailscale:** App Store build 1.104.2 on this Mac (2026-11-16).
- **Libraries** (Swift package `TailshareCore`, pinned by `Package.resolved`): Hummingbird 2.17.0, ZIPFoundation 0.9.20. Hummingbird 2.18 and later need Swift tools 6.2, newer than Xcode 16.2's.

## Codebase Map
- `TailshareCore/` — a local Swift package: protocol (`Protocol.swift`), receiver (`Receiver.swift`), sender (`Sender.swift`), bundles, names, settings and trust, the Tailscale CLI wrapper, notification text, link detection, the share hand-off link (`HandOff.swift`), and `Node.swift` (one `refresh()` is the whole 10-second re-check), `PopupPlacement.swift` (where the popup hangs). Its tests are in `TailshareCore/Tests/`.
- `Tailshare/` — the app target: menu-bar icon and popup (`PopupController.swift`, AppKit; SwiftUI views inside), send window, first-contact window, notifications, login item, the `tailshare:` link handler. Hosts Core.
- `ShareExtension/` — the Share Extension target.
- `Tailshare.xcodeproj` — one project, two targets (no test target). It was generated by a script outside the repo; edit it in Xcode from now on, and add new Swift files to it there (the project lists files one by one).
- `Shared.xcconfig` — both targets' base configuration; includes `Local.xcconfig` when it exists.
- Invariants:
  - **Only Core's receiver writes into the receive folder, and only inside it.**
  - **Only Core's settings store writes the settings file.**
  - **Core never imports AppKit or SwiftUI.**
  - **The Share Extension does no network I/O and never runs the Tailscale CLI.**
  - The main app is not sandboxed and uses no capability that needs a provisioning profile (no App Groups, no iCloud).

## Commands
- **Test** (from the repo root): `swift test --package-path mac/TailshareCore`, or the same suite through Xcode: `xcodebuild test -scheme TailshareCore -destination 'platform=macOS'` run inside `mac/TailshareCore`. 91 tests; `swift test` takes about 5 seconds including the build, the suite itself about 4; `xcodebuild test` about 1 minute 16 seconds on a first run, which builds everything (2026-11-17). If a run could outlast a tool call's 2-minute default, give it a longer timeout.
- **Build, signed Release** (from the repo root): `xcodebuild -project mac/Tailshare.xcodeproj -scheme Tailshare -configuration Release -derivedDataPath mac/build/DerivedData build`. Signs with the Personal Team from `Local.xcconfig`. The product is `mac/build/DerivedData/Build/Products/Release/Tailshare.app` (`mac/build/` is ignored by git). About 1 minute 23 seconds on a first build, 16 seconds when little changed (2026-11-17).
- **Install:** quit any running copy first, by PID: `kill $(lsof -nP -iTCP:45611 -sTCP:LISTEN -t)`. Then `ditto mac/build/DerivedData/Build/Products/Release/Tailshare.app /Applications/Tailshare.app` (a fraction of a second, worked 2026-11-17), then `open /Applications/Tailshare.app`.
- **Run:** the installed copy above. The first launch registers the login item and asks for the notification permission; Downloads access is asked on the first receive. The Share Extension shows in the share sheet once it is switched on in System Settings → Extensions → Sharing.
- **A copy for the target Mac:** `ditto -c -k --keepParent /Applications/Tailshare.app Tailshare.zip`; unzip into `/Applications` there and approve it in Privacy & Security → Open Anyway (each updated copy may ask again).
- **Dev port:** 45611 (the default; `port` in the settings file overrides it, but the dev loop uses the default), with the same rule as the root *Commands*: it's the port every peer connects to, so if it's occupied, **stop and ask me to free it**; never reassign it. The dev loop and the installed copy can't both run.
- **Stray processes:** a session stops what it started, by PID, never `pkill -f`.
- **Mutation:** no tool; the Implement session ran about 75 hand-listed mutants over Core, one `swift test` each, in a copy of the package made **without** its `.build` (a copied `.build` fails every build on absolute paths), about 8 seconds each, about 15 minutes in all (2026-11-17).
- Lint / format: none.
